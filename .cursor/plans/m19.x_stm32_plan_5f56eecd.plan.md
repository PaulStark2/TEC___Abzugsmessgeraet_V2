# M19.x STM32-Integrationsplan (Stand 2026-10-07)

## 1. Executive Summary

Software bis **M19.0** plus Kraftkalibrierung (Core/Sim/GUI) ist auf PC+Sim fertig. `firmware/` **Phase 1–5a im Code** (M12 auf Host-UART + GUI `PROTOCOL_TRANSPORT=uart`).

Zielarchitektur:

- **HMI** = GUI, JSON, Persistenz, M12-Client. Keine Echtzeit-Motion, keine Kraftregelung.
  - **Bring-up:** Laptop (GUI lokal) ↔ ST-Link VCP ↔ **USART2** PA2/PA3
  - **Produktion:** Raspberry Pi (Kiosk 10″) ↔ **USART3** PC10/PC11
- **STM32F446RE = Controller**: derselbe `core/` plus HAL hinter `HostInputs` / `HostOutputs`.
- **M12**: zwei Transports, eine HMI. **TCP :8766 → Simulation** (Default) und **UART → STM32**. Genau ein Controller zur Zeit. Genau **ein** Host-UART trägt M12 (kein Dual-M12).

Die Simulation wird nicht abgelöst. Default bleibt Simulation, damit ein versehentlicher Jog nicht die Mechanik bewegt.

**IDE:** Cursor + CMake; CubeMX für die Pin-Matrix; CubeIDE nur Debug/Flash. Core nicht in ein CubeIDE-Projekt kopieren.

---

## 2. Bereits implementiert

- **Core:** Axis, MotionPlanner, Machine, ProcedureController, Homing, ForceWatchdog, ProbeCalib, SafeZ, **ForceCalibration** (`F = β0 + β1·adc + β2·adc²`)
- **M12:** Frame `TE` + CRC-16, StatusReport **41 B**, MachineConfig **356 B** (`force_range_N`, harte Grenze und Kollisionsgrenze je Achse, `a_manual`; Default ±30 N, Handbeschleunigung 500 mm/s²). Kraft-Nachrichten `0x59` / `0x5A` / `0x5B` / `0x5C` / `0xA4` / `0xA5`
- **Sim/GUI:** TCP `:8766`, SimPlant, ProtocolMachineClient, `calibration.json`, Force-Wizard, Connect-Push der Kennlinie
- **Firmware Phase 1:** `firmware/` CMake arm-none-eabi 14.2, 180 MHz, IWDG, 1 kHz `Machine::tick`, LED PC7
- **Firmware Phase 2 / 2.1:** ADC1 DMA PA0/PA1/PA4, GPIO Limits/E-Stop/Probe, Spreizer PC8/PC12, Fixture PC9, UART-Echo derzeit fest auf **USART3**

Provisorische Firmware-Kraft bis Phase 7: linear **0…4095 → ±`force_range_N`** (Default ±30 N). Zielvertrag: [docs/Force_Calibration.md](docs/Force_Calibration.md).

---

## 3. Fehlende STM32-Komponenten (nach 2.1)

Noch offen: Probe-EXTI Feinschliff (1 kHz Poll-Latch in FirmwareHost ist verdrahtet), Phase 5b Pi-USART3, Step-Signal Oszi-Feinschliff, Phase 8 Kraftregelung. Phase 6: Prozess-Tick + `CmdNop`-Heartbeat verdrahtet; GUI-e2e Start noch Bench.

`HostOutputs` bleibt ohne Step/Dir — Firmware liest die Core-Sollpose nach `tick()`. Enable wird nicht vom STM32 geschaltet.

---

## 4. Architektur und Datenfluss

GUI → Host → M12 → CommandDispatcher → Core → HostOutputs → Hardware; Sensoren → HostInputs → Core → StatusReport → Host → GUI.

**Raten:** Core/ADC **1 kHz**, StatusReport **50 Hz**, Host-`CmdNop` **10 Hz** sobald die UART-Session steht.

**Umschalter** (Phase 5): `MACHINE_CLIENT=protocol` plus `PROTOCOL_TRANSPORT=tcp` (Default) | `uart`. Niemals zwei Controller. Plant-3D nur bei `tcp`. Persistenz gilt für beide Ziele.

```text
Bring-up:   Laptop GUI  --ST-Link VCP COMx-->  USART2 PA2/PA3  --> STM32
Produktion: Pi Kiosk    --/dev/serial0------>  USART3 PC10/PC11 --> STM32
```

---

## 5. Hardware-/Pin-Schnittstelle (fest)

STM32-GPIO 3,3 V. Limits und E-Stop **High = aktiv**. Messtaster **NC, Low = Kontakt**. Step/Dir über **5-V-Pegelwandler** auf DM542. ENA **unbeschaltet**.

**Konfliktcheck F446RE**

- PA0/PA1/PA4 = ADC1 IN0/IN1/IN4 — DAC auf PA4 nicht aktivieren
- PA2/PA3 = USART2 **ST-Link-VCP**. SB13/SB14 **geschlossen lassen**. Bring-up-Host-UART (M12/Bench); kein Pi auf diesen Pins
- PA5 Probe = EXTI später, intern Pull-Down. Nucleo LD2 nicht nutzen
- Step: PB6 TIM4 (X), PB4 TIM3 (Y), PB8 TIM10 (Z). I2C1 auf PB8 nicht aktivieren. PB4 NJTRST: nur SWD
- PC10/PC11 = USART3 AF7 zum Pi (Produktions-Host-UART). SPI3/UART4/SDIO auf diesen Pins nicht aktivieren
- PC7 = Debug-LED (kein Reserve mehr)

**Pin-Matrix**

- **PA0** ADC1_IN0 — Fx
- **PA1** ADC1_IN1 — Fy
- **PA2** USART2_TX — ST-Link VCP (Bring-up Host-UART wenn `TEC_HOST_UART=USART2`)
- **PA3** USART2_RX — ST-Link VCP
- **PA4** ADC1_IN4 — Fz
- **PA5** Probe NC, Pull-Down, Low = Kontakt
- **PA6** X+ Limit (Homing-Referenz X) — High = aktiv; Firmware **10 ms** Debounce (`HostIo`); externer Pull-Down (4k7…1k) + kurze Leitung / optional RC gegen Stepper-EMI
- **PA7** Y+ (dito)
- **PA8** Z+ (dito)
- **PA9** E-Stop High = aktiv (Lastabschaltung parallel Hardware; **kein** Software-Debounce)
- **PA10** X− (dito Limits)
- **PA11** Y−
- **PA12** Z−
- **PB4** TIM3_CH1 Y Step
- **PB6** TIM4_CH1 X Step
- **PB8** TIM10_CH1 Z Step
- **PC1 / PC3 / PC5** DIR X/Y/Z (High = +Maschine, firmware-invertierbar)
- **PC7** Debug-LED
- **PC8** Spreizer **öffnen**
- **PC9** Fixture (einzelnes Ventil, Halter offen)
- **PC10** USART3_TX → Pi RX (GPIO15) — Produktion
- **PC11** USART3_RX ← Pi TX (GPIO14) — Produktion
- **PC12** Spreizer **schließen**
- **PB7 / PC0 / PC2 / PC4 / PC6** Reserve

**Spreizer-Paar (doppeltwirkend)**

- Öffnen: PC8=1, PC12=0
- Schließen: PC8=0, PC12=1
- Niemals beide High. Ein Pin allein ist ungültig
- Core: `setSpreaderExtend(true/false)` bleibt ein Kommando. Firmware mappt `SpreaderState`
- E-Stop/Fault: **Freeze** der letzten gültigen Paar-Beschaltung (`SafeDeenergized` ändert die Pins nicht). Hardware trennt die Druckluft trotzdem
- Boot: GPIOs kurz beide Low, erstes Core-Tick `Retracted` → Schließen-Paar

**Host-UART:** Compile-time `TEC_HOST_UART=USART2|USART3`. Genau eine Instanz trägt Bench/M12. Bring-up-Default **USART2** (Laptop ST-Link COM). Produktion **USART3**. Kein Dual-M12. `firmware_hwtest` Dual-Console bleibt nur für ASCII-HW-Tests.

## 6. Motion

Core float mm; Firmware int32 Steps. **Zielkinematik:** 57HS56, 1/4 µstep, SFU1204 → **200 steps/mm**. DIR High = +Maschine. CMake: `TEC_STEPS_PER_MM` (Default 200).

**Testkinematik (aktuell am Bench):** Lineare Achsen eines alten **Zortrax M300**, nicht die Ziel-SFU. Per-Achse via CMake (`TEC_STEPS_PER_MM_*`).

**Messung 2026-10-14** (Jog 10 mm Software → Istweg):

| Achse | Mechanik | Alt (zu schnell) | Istweg bei 10 mm Soft | Neu |
|-------|----------|------------------|------------------------|-----|
| X/Y | Riemen | 40 | **40 mm** (Faktor 4) | **10** = 40×(10/40) |
| Z | Kugelgewinde | 800 | **46 mm** (Faktor 4,6) | **≈173,913** = 800×(10/46) |

Formel: `steps/mm_neu = steps/mm_alt × (mm_soft / mm_ist)`.

**Stand 2026-10-15 (ersetzt die Tabelle oben):** Die Testspindel ist **4 mm/U** bei 1/4-µStep. 800 rohe Pulse = eine Umdrehung → **Z = 200 steps/mm**. X/Y nach dem One-Pulse-Fix: Soft 10 mm → real 5 mm bei 10 steps/mm, also **X/Y = 20**. Die früheren Werte (XY 10, Z 173,9 und 114,3) haben Extra-Flanken des alten PWM-Stopps mitgemessen. Der Step-Generator gibt pro Software-Schritt genau eine steigende Flanke aus (One-Pulse PWM2).

**Vor dem Einsatz der Zielkinematik zwingend alle Achsen wieder auf 200** (`TEC_STEPS_PER_MM=200`, Achsen-Overrides leeren) und neu flashen.

Software-Safety: XY 50 mm/s, Z 25 mm/s über MachineConfig (Compile-Time `kMaxVelocity = 50` für alle Achsen). Puls bei 50 mm/s × steps/mm (Ziel: 10 kHz bei 200).

**Arbeitsraum 300 × 200 × 130 mm** (nicht 400×400). Ursprung weiter +Max, Workspace negativ. Soft-Limits bleiben Schalterbits; keine Core-Travel-Box in diesem Strang. Sim-Plant-Defaults 100/100/50 sind virtuell und bleiben. Phase-4-Testdistanzen ≤ 300/200/130 mm.

Homing: Z+ → X+ → Y+ an +Max. Open-Loop.

E-Stop: Hardware trennt Motor+Pneumatik; STM32 Fault; PWM aus; Spreizer-GPIO freeze.

## 7. Sensor / Aktor

**Kraft** (Messung STM32, Regelung Core, Vorzeichen wie [docs/Force_Calibration.md](docs/Force_Calibration.md): Zug negativ, kein Host-Flip):

- Phase 2.1: DMA-Rohwerte + provisorisch `F = -R + (counts/4095)*2R` mit `R = force_range_N`
- Phase 7: `MsgRawAdc`, `0x59`/`0x5A`/`0x5B`, dieselbe `ForceCalibHost`-Logik wie die Simulation, Polynom auf allen drei Kanälen
- Watchdog gegen `hard_limit_N` (Default 30 N), Phasengrenzen aus MachineConfig. `SafetyLimits` 500 N ist nur Tippfehler-Bremse
- Dosen-Ruhe in der Sim-Ankerlage ~1,5 V, nicht 1,65 V. Offene Analogpins können Fault auslösen
- `docs/M18_Procedure.md` (Zug positiv) ist für STM32 **nicht** maßgebend

**Messtaster:** NC, Pull-Down an **PA5**, Kontakt = Low. Core-Vertrag: Host muss an der Kontaktflanke **Pose + Sequence** in `HostInputs` legen — Level allein wird ignoriert ([docs/M19_ProbeCalibration.md](docs/M19_ProbeCalibration.md)). Firmware: `FirmwareHost` 1-kHz-Poll-Latch (wie SimPlant-Ereignis). Optional später EXTI. Nucleo: LD2 oft auf PA5 — Brücke trennen. Hardware-Feinantasten: GUI `v_search_fine = 0,1` mm/s.

**Aktoren:** 3× DM542, Spreizer PC8+PC12, Fixture PC9, keine Endlagen-Sensoren.

## 8. Kommunikation

**Physik (115200 8N1, kein Flow-Control):**

| Pfad | Host | STM32 | Pins |
|------|------|-------|------|
| Bring-up | Laptop ST-Link VCP (`COMx`) | USART2 | PA2 TX / PA3 RX |
| Produktion | Pi PL011 `/dev/serial0` | USART3 | PC10 TX / PC11 RX |

Pi: GPIO14 TX → PC11, GPIO15 RX ← PC10, Serielle Konsole aus. SB13/SB14 bleiben geschlossen.

GUI-Env (Phase 5): `PROTOCOL_TRANSPORT=tcp|uart`, `PROTOCOL_SERIAL_PATH=COMx` bzw. `/dev/serial0`. Default `tcp` (Simulation).

Heartbeat unverändert: `CmdNop` 10 Hz auf der Session; Core-Watchdog nur im Automatic. Timeout → Fault + Freeze, kein Auto-Resume.

GetMachineConfig **356 B** — falsche Länge → GUI offline.

## 9. Firmware-Architektur

```text
firmware/
  HostIo          ADC DMA, Host-UART (TEC_HOST_UART) echo/M12, Limits, Spreizer-Paar, Fixture
  FirmwareHost    1 kHz Machine::tick
  StepGenerator   Phase 3+  (TIM4/3/10)
  ProbeLatch      Phase 4/5 (EXTI PA5)
  UartLink        Phase 5   115200, FixedFrameBuffer 520 B auf gewähltem Host-UART
core/ + communication/  linken
```

CommandDispatcher nicht mit Sockets aufs MCU ziehen. Bevorzugt transportfreies Dispatch-Modul (Sim + Firmware). ForceCalibHost in Phase 7 aus `simulation_bridge` in ein HAL-freies Modul.

## 10–11. Zustände und Safety

Core-Enums unverändert. Hardware-E-Stop + PA9. IWDG. Schrittverlust: erneutes Homing. Spreizer nach Fault elektrisch eingefroren, mechanische Lage ohne Sensor unbekannt.

## 12. Offene Punkte vor dem ersten Motor-Move

1. **5-V-Pegelwandler** PUL+/DIR+ verdrahten und oszilloskopieren
2. DM542 DIP 1/4-step, Strom gegen 57HS56
3. Ruhe-Spannung Fx/Fy/Fz messen (Anker ~1,5 V, nicht 1,65 V)
4. `TEC_HOST_UART=USART2` flashen; Phase-2.1-Bench am Laptop-ST-Link-COM
5. Später GND Pi–Nucleo–Treiber; Pi-UART an **PC10/PC11**

Nicht: SB13/SB14 öffnen.

Später: STM32-Flash-Persistenz, `force_filter`, per-Achsen-Z=25 Compile-Time-Limit. Kraftkalibrierung auf dem STM32 ist Phase 7 (GUI/Sim sind fertig).
